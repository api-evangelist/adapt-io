# Adapt

> Adapt (adapt.io) is a B2B lead intelligence and sales acceleration platform selling
> access to a database of 250M+ verified business contacts and 12M+ company profiles.
> The Prospect API v3 exposes four operations — contact search, company search, contact
> enrichment, and contact purchase — over JSON/HTTPS at https://api.adapt.io/v3.

Adapt does not publish an llms.txt. This file is generated by API Evangelist from the
provider's own developer reference (https://www.adapt.io/api-docs/v3/) and the artifacts
in this repository. Generated 2026-08-13.

Important for agents:
- API access is gated to Adapt's Custom (enterprise) plan. Free, Starter ($49/mo) and
  Basic ($99/mo) tiers do not issue Prospect API credentials.
- Authentication is TWO custom headers, not Authorization/Bearer: `email` (the account
  email) and `apiKey` (from https://leads.adapt.io/profile/settings).
- Every operation is a POST with a JSON body. There are no GET endpoints.
- HTTP 200 does not mean a match. Branch on the `code` field: APP-200-001 is success,
  APP-200-002 is "No results found".
- POST /contact/fetch SPENDS email and phone credits and is not idempotent. Confirm
  before calling it and track purchased ids client-side.
- adapt.io's robots.txt disallows all user-agents except a named list of search
  crawlers. Agents fetching adapt.io pages are outside that allow-list.

## API

- [Prospect API reference (v3)](https://www.adapt.io/api-docs/v3/): The complete
  published reference — authentication, rate limiting, error handling, and all four
  operations with input parameters, response headers and output fields.
- [API product page](https://www.adapt.io/platform/api): What the API is sold as and
  which plan includes it.
- Base URL: https://api.adapt.io/v3

### Operations

- `POST /contact/search` (searchContacts): Search contacts by name, title, level,
  department, company name/domain/keyword, head count, revenue, industry, sub-industry,
  technology and location. Returns contacts WITHOUT email; each carries an `id` for
  purchase. Cursor-paged via `cursorMark` + `limit`. Consumes search credits.
- `POST /company/search` (searchCompanies): Search companies by name, domain, industry,
  sub-industry, head count, revenue and location. Returns firmographics plus
  `numberOfContacts`. Cursor-paged. Consumes search credits.
- `POST /contact/enrich` (enrichContact): Enrich one known contact from ONE of three
  input combinations — `email`, or `linkedinURL`, or `firstName` + `lastName` +
  `domain`. Use `include: ["EMAIL","PHONE"]` to opt into the billable fields. Consumes
  enrichment credits.
- `POST /contact/fetch` (purchaseContacts): Reveal email and phone for up to 50
  `contactIds` returned by contact search. Consumes email and phone credits.
  Irreversible.

### Runtime semantics

- Rate limit: 250 requests per minute per account. Headers `x-ratelimit-limit`,
  `x-ratelimit-reset`, `x-ratelimit-retry-after`. Status 429 with code APP-429-001.
- Credit balances are returned on every call: `x-call-credit-type`,
  `search-remaining-credits`, `enrich-remaining-credits`, `email-remaining-credits`,
  `phone-remaining-credits`.
- Response envelope: `{message, code, data, cursorMark, totalResults}`. `data` is an
  object for enrichment and an array elsewhere.
- Errors: proprietary `{message, code}` with APP-nnn-nnn codes. Not RFC 9457.
  403/APP-403-003 is credit exhaustion and will never succeed on retry; 429 will.
- No webhooks, no events, no idempotency keys, no request ids, no status page, no
  changelog, no SDKs, and no MCP server.
